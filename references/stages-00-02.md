# 阶段 00–02：材料、模型总图与数据管线

仅在用户明确调用 `lingerskill` 后使用。阶段编号是讲解导航，不是必须逐关完成的流程；围绕用户正在读的段落或模块展开即可。默认直接在聊天中回答，不建立状态文件或论文卡片。

## 00 · 明确可读材料与讲解范围

优先读取论文正文、附录，以及论文或作者正式页面链接的官方代码。记录足以准确引用的标题、论文版本和来源；代码能确认版本时记录 tag/commit，不能确认时不要补造。不要因缺少代码或非关键配置阻塞论文讲解。

材料不足时说明范围：只有摘要就只解释摘要能支持的内容；全文或官方仓库无法访问时简短说明，继续解释可见材料。第三方复现可以作为补充，但必须标明它不是作者实现。

把事实和示意区分开：

- `[P]`：论文或附录明确陈述，附可回读的位置。
- `[C-static]`：实际读到的官方代码行为，附文件及类/函数；可确认时附行号和版本。
- `[R]`：实际读到的相关前作，附其来源与位置。
- `[I]`：为理解而作的推导、简化或教学示意，说明假设。
- `[U]`：材料未说明或尚不能确认，不凭常识补成论文事实。

关键架构、数据处理、模块功能和贡献判断应就地给出原文定位，例如 `§3.2，Fig. 2，Eq. (4)，PDF 第 6 页`。只填写真实存在且已检查的定位；正文页码与阅读器页码不同则注明采用哪一种。没有页码的网页可用小节标题、图/公式编号和段落开头短语定位；代码使用 `path/to/file.py::Class.method`，有真实行号再添加。不要用一个论文首页链接替代所有具体证据，也不要编造页码。

## 01 · 先建立问题与模型总图

先用通俗语言交代作者要解决什么问题、输入是什么、输出是什么，以及整体设计思路。用户未指定应用背景时不擅自套入某个领域。

给出一条可沿着阅读的主路径，例如：

`原始序列 → 预处理/窗口 → 输入表示 → 主干模块 → 分支融合 → 预测头 → 输出恢复`

这只是表达方式，实际节点和顺序以论文为准。存在并行分支、串联、跳连、共享模块、跨层信息传递时，要在图或文字中表现出来，不能把它们全部压成一条串行箭头。指出总图中每个模块的职责，并关联原文的架构图和对应小节。

用少量符号建立共同语言：例如论文采用常见时间序列布局时可写 `X ∈ R^{B×L×C}`，分别解释批次、历史长度和变量数。不能因为这一布局常见就强行覆盖论文自己的轴顺序、输出变量或预测方式。

这一部分通常只需：问题与核心思路、一张结构图或主路径、最值得回读的图/小节。无需额外生成“论文卡”。

## 02 · 跟随一批数据解释处理过程

按实际先后顺序追踪一批数据从来源到预测结果的流动。重点回答每一步“做了什么、为什么做、数据的意义或形状如何变化”。表格可按复杂度选用，不要求填满不存在的步骤。

| 流程节点 | 输入与含义 | 处理及目的 | 输出/轴含义 | 原文或代码定位 |
|---|---|---|---|---|
| 数据读取与划分 | | | | |
| 缺失值/归一化等预处理 | | | | |
| 历史窗口、标签、时间或外生特征 | | | | |
| Batch 与模型输入 | | | | |
| 模型内变换与预测输出 | | | | |
| 损失所用表示、预测恢复 | | | | |

选择影响理解的细节展开：

- **归一化：** 使用哪些统计量、按哪个轴处理、统计量何时取得、模型输出是否需要逆变换。区分数据集级标准化与模型内逐样本归一化，讲清两者各自的位置和目的。
- **窗口与标签：** 哪一段历史构成输入、哪一段构成标签，时间特征和外生变量怎样对齐。训练时提供标签不等于预测时把标签送入模型；解释训练与预测的输入差别。
- **时域/频域或分解：** 若论文确有 FFT、滤波、趋势/季节分解等，解释沿哪个轴计算、表示如何改变、哪些分量进入后续模块、是否以及如何回到原表示。
- **Batch 与张量轴：** 时间、变量、Patch、频率、隐藏特征各轴的语义是什么。只追踪影响理解的变换，不穷举每个内部算子。
- **训练与预测出口：** loss 接收什么输出和标签、二者处于什么尺度；最终预测是否逆归一化、拼接或裁剪。按材料说明顺序，不预设所有论文都在同一尺度计算 loss。

若需要具体数字帮助理解，可使用一个小例子，明确标为 `[I] 教学示例，非论文实验配置`；不能把示例长度、通道数或超参数写成作者设置。

阅读目标是理解作者的处理思路。默认不把归一化、划分和未来特征讨论扩展成泄漏审计、代码缺陷清单或测试任务。材料间存在会影响讲解的歧义时，简短并列说明论文表述与代码行为，标明未确认处即可。
