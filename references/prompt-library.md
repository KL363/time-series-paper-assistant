# 分阶段调用词库 / Prompt Library

> 用户不必把下面所有内容一次发送给 AI。此文档提供最小指令；具体执行以 `SKILL.md` 和 `references/stages-*.md` 的程序为准。

## 00 总控/开始新论文

```
使用 time-series-paper-auditor 对这篇时序预测论文建立一个新的分析档案。
模式：[quick/deep/reproduce]。
论文：[上传 PDF / 填入标题或链接]；官方代码：[链接及可选 commit]；领域：[领域名称]；预测对象：[目标]。
优先关注：[数据管线/张量/频域/变量关系/创新性等]。
先列出已获得材料、缺口和阶段计划；遵守 [P]/[C-static]/[C-run]/[R]/[I]/[U] 证据纪律。
```

## 01 论文定位

```
执行阶段 01。识别研究任务、问题定义、输入输出、预测长度、核心假设、主干结构和作者声称的贡献。区分论文声明与独立核实；最后给出最应该深入读的三个模块及原因，附定位。
```

## 02 数据管线与未来可用性

```
执行阶段 02。以预测发起时刻 t 为边界，完整追踪原始数据→划分→拟合预处理→窗口→Batch→模型输入→输出→反归一化→评价。对每步写张量形状、数据可用时间、数据泄漏风险与证据；区分未来已知/未来预测/真实未来观测。
```

## 03 模型结构与逐算子 Tensor Shape

```
执行阶段 03。从完整模型计算图开始，按 forward 顺序列出每个核心操作的输入 Shape、运算、实际交互轴、输出 Shape、设计动机和来源。重点检查 Attention、FFT、Patch、Conv、Normalize、Flatten/Reshape 等；使用合法小张量例子手工验算，绝不编造维度。
```

## 04 论文—代码逐项对照

```
执行阶段 04。以指定 Git commit / 配置为准，顺着数据加载、Model.forward、子模块、预测头、loss 和 evaluation 的真实调用链，对照论文公式与源码。输出 `论文位置→文件/函数→操作→输入/输出 shape→一致性→证据`。严格区分 C-static 与 C-run；如能安全执行，给最小断言/Hook 的具体测试结果，否则列待运行测试。
```

## 05 模块创新性与前作比较

```
执行阶段 05。逐模块识别直接复用、组合、改造、新机制或训练创新。必须具体比较已有前作的 Token 定义、公式、交互轴、融合方式和训练协议，建立创新来源矩阵。避免把作者声称的 novel 当作证据；缺少前作就标 U 并给出检索建议。
```

## 06 评估和消融审计

```
执行阶段 06。审查时间划分、外生变量的可用性、Baseline 公平性、训练/调参预算、参数与计算成本、多个随机种子，以及每个模块的对应消融。严格区分“有性能贡献”与“证明特定机制”。最后推荐最有解释力的补充实验。
```

## 07 创新假设与最小实验

```
执行阶段 07。我的应用领域是 [领域]，预测目标为 [任务]。结合已核验的模型限制，提出最多三个可证伪的结构改进假设。每个方案说明修改位置、公式/shape 变化、前作关系、对照组、计算成本、预期观察和否定条件。不要简单堆叠热门模块，不保证涨点。
```

## 08 知识库沉淀

```
执行阶段 08。将已验证结果整理为 Paper Card、核心 Module Card、Research Hypothesis Card。保留证据定位、代码版本和不确定事项，不要让阶段早期的推断在总结中自动升级为事实。
```

## 追问快捷指令

- **单模块深挖：**“只解析 `<模块>`，逐算子追踪 forward，列出张量形状、Attention/卷积计算轴、参数共享以及对应数学公式，不要总结其他模块。”
- **反证审查：**“尝试找到你刚才结构解释中可能错的地方。尤其检查 reshape 后 Token 的含义、Q/K/V 的最后两轴、归一化的统计轴；不能确认就列出代码断言。”
- **来源对比：**“只对比本文 `<模块>` 与 `<前作模块>`，逐项给出相同公式、不同计算路径和是否等价，并注明证据。”
- **最小复现实验：**“为 `<假设>` 制定参数量/输入信息尽可能匹配的 Baseline、替代模块、消融及失败判据。”
- **继续工作：**“读取上一阶段的已确认结论与 U 列表，执行下一阶段，先解决最影响结论的 1–3 个问题。”
