# lingerskill 使用指南

## 阅读重点

lingerskill 帮助你理解作者为什么采用这种架构、数据怎样进入模型、每个模块做什么、训练怎样进行，以及作者复用、组合、改造或提出了哪些方法。关键解释附原文定位，便于回到相应章节、图或公式继续阅读。

默认直接在聊天中讲解，不创建分析档案、阶段状态文件或多份笔记，也不要求运行代码或复现实验。

## 安装与触发

将完整项目放入客户端支持的 Skills 搜索路径，安装目录名使用 `lingerskill`，保留 `SKILL.md` 与同级资源的相对位置。现有仓库目录可以继续叫 `time-series-paper-auditor`。具体安装路径和加载方式按客户端说明执行。

提供论文 PDF 或可访问链接，然后发送：

```text
使用lingerskill给我讲解这篇论文。
```

`agents/openai.yaml` 设置 `policy.allow_implicit_invocation: false`，入口也要求明确点名。自然语言能否发现技能取决于客户端；必要时先用 `$lingerskill` 或技能选择器显式选择。

普通“帮我读论文”不会主动启用。同一篇论文启用后，可以用“继续解释频域模块”承接；换论文时需要重新明确调用。要求停止使用后，后续恢复普通回答。

## 一条完整指令

```text
使用lingerskill给我讲解这篇论文。
先给出整体架构与数据流，再讲每个核心模块的功能和来源。
追踪归一化、分块或频域处理、模型前向传播、损失与参数更新，附原文定位。
有官方代码就结合代码讲，没有就用教学伪代码。直接在聊天里回答。
```

如果知道官方代码地址，可以一并提供。commit/tag 有助于锁定版本，但不是开始阅读的前提。

## 如何读回答

- **架构与数据流：** 从输入输出和计算图开始，逐步解释原始数据、预处理、batch、模块与预测。张量维度要说明时间、变量、patch、频率等实际含义。归一化说明统计量来源和作用轴，频域处理说明变换轴、表示及如何回到时域；只讨论论文实际使用的步骤。
- **模块与贡献：** 讲清输入、操作、输出、动机与上下游关系，区分直接复用、组合、改造、新机制及数据或训练贡献。这些类型可以重叠，不是优劣排名；已有模块的使用不自动否定科研贡献。
- **原文定位：** 关键解释附近给章节、图号、公式号或明确页码口径的 PDF 页码。代码用文件、函数及可确认的行号定位。不可核对的位置不编造。
- **事实与推断：** 按需使用 `[P]` 论文、`[C-static]` 静态代码、`[C-run]` 实际运行、`[R]` 前作、`[I]` 推断、`[U]` 未确认。作者声明与前作核对结果分开，缺少材料时保留不确定性。

有官方代码时，沿数据加载、预处理、`forward`、子模块、预测头、损失、参数更新和推理入口静态讲解。只读源码不写成运行验证。没有代码、链接不可访问或部分未开放时，缺失路径用教学伪代码解释，标明论文给出的步骤、示意与未知配置。伪代码不是作者的原始实现或可复现保证。

影响理解的论文与代码差异会简要说明，默认不扩展为代码挑错清单、实验审计或待运行测试计划。

## 继续追问

同一篇论文启用后，可直接说：

- “只讲这个频域模块，用小张量说明数据形状怎么变，并定位到公式。”
- “从一批原始数据开始，逐步讲到 loss 和参数更新。”
- “这些模块哪些是复用，哪些是改造？给我原文和引用位置。”
- “代码缺少训练部分，请用教学伪代码接上，标明未知配置。”
- “给我最值得自己回读的三处原文，以及各处要看懂什么。”

独立会话或换论文时，在请求前加“使用lingerskill”。更多例子见 [提示词库](prompt-library.md)。

## 可选扩展

阶段 00–05 覆盖材料、问题总图、数据、模块、代码或伪代码、来源，按当前问题灵活组织，不机械逐段输出。以下内容仅在明确请求时进入：

| 阶段 | 示例请求 |
| --- | --- |
| 06 实验讨论 | “检查实验与消融是否支持作者结论。” |
| 07 研究方案 | “提出可检验的研究改进想法。” |
| 08 导出 | “将这次讲解导出为一个 Markdown 文件。” |

“整理一下”“做个总结”默认仍在聊天中完成。只有明确要求保存、导出或创建文件时才写文件，并优先生成满足需求的最少数量。

## 维护

`SKILL.md` 负责触发与路由，`references/` 放按需加载的讲解规则，`assets/` 用于明确请求的导出，`scripts/` 提供可选工具。修改后运行结构检查，并检查普通请求、显式调用、无代码、官方代码和明确导出等场景；无需为维护技能而执行第三方论文仓库。
