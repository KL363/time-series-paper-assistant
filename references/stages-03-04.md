# 阶段 03–04：模块机制与代码/伪代码讲解

本文件服务于已经明确调用的 `lingerskill`。按问题选择重点模块和必要计算，不要求每层、每个算子都展开，也不以运行验证作为讲解前提。

## 03 · 从模型总图进入核心模块

覆盖架构中的各具名模块，包括复用的预处理和预测头；通用基础算子可归并，重点模块深入展开。先说明模块在整体数据路径中的位置，再回答：

1. **为什么有它：** 作者希望捕捉什么关系或解决什么问题？区别作者明确动机与自己的解释。
2. **接收与输出什么：** 输入、输出的语义和形状；主要张量轴是时间、变量、Patch、频率还是隐藏特征。
3. **怎样计算：** 用通俗语言说明机制，再对齐关键公式、符号和必要算子；解释数字计算与信息交互各发生在哪个轴。
4. **怎样连接：** 与前后模块串联还是并行，分支在何处拼接、相加或加权融合，跳连绕过什么处理，哪些参数共享。
5. **从哪里来：** 作者新提机制、对已有模块的改造、已有模块组合，或直接采用常用部件。模块来源的详细判断见阶段 05，不能把模块名字当成原创证据。

核心结论就地关联论文的小节、图、公式或页码；代码可以补足执行细节，但不能替代论文对设计动机的陈述。

复杂模块可使用紧凑表格：

| 模块/关键操作 | 输入及轴含义 | 主要计算与作用 | 输出及去向 | 原文/代码位置 |
|---|---|---|---|---|

### 选择真正影响理解的细节

- `reshape/permute/transpose` 改变布局时，说明轴如何映射；把变量并入 batch 通常表示共享处理，并不自动产生跨变量交互。
- Attention 要说清 token 代表时间点、Patch 还是变量，以及 Q/K/V 来自哪里、谁与谁交互。只有在用户需要时再展开多头维度和完整矩阵形状。
- Patch 要说明窗口、步长及 padding 如何影响 token 数；若用 `N = floor((L-P)/S)+1`，注明无 padding 且 `L≥P` 的前提，实际策略仍以来源为准。
- 频域模块要说明 FFT 的轴、复数表示或幅相处理、频率选择与逆变换。只有确实采用实数 FFT 时才使用 `floor(L/2)+1` 个频率点这一关系。
- 卷积、归一化和预测头优先解释处理对象及建模目的，不依据名称猜测长度保持、归一化轴或自回归方式。
- 多分支与残差要说明每条支路保留了什么信息、融合时各自贡献什么。图、公式与代码有不同表达时分别标明来源，必要时保留歧义。

为帮助理解可手工推导一个小尺寸例子，但要标为 `[I]`，说明采用的假设。不要把手工推导称为运行结果，不要求额外安装依赖、hook、dry run 或测试。

## 04 · 用官方代码或教学伪代码串起完整过程

### 有可访问的官方实现

从论文或作者正式页面确认仓库，按需静态阅读最相关文件。目标是解释执行过程，而不是审查仓库质量。

优先串起这条调用链；若仓库组织不同就按实际结构解释：

`数据读取/Dataset → 预处理与取窗 → DataLoader → Model.forward → 核心子模块 → loss 与参数更新 → 预测及逆处理`

重点讲清：

- 一批输入和标签如何形成，配置如何决定必要的长度、维数或模块开关。
- `forward` 如何调用各模块，数据在哪些位置改变表示、分流和融合。
- loss 如何比较输出与标签，训练循环如何据此更新参数；优化器、停止条件等只解释实际材料中出现且与问题相关的内容。
- 推理时与训练时有什么流程差别，模型输出如何恢复为用户关心的预测量。

用 `文件::类/函数` 对应论文的模块/公式；读到了具体行号和版本才给出行号/commit。代码观察标 `[C-static]`。不要凭常见项目结构编造路径或声称执行过代码。

| 论文中的步骤与定位 | 官方代码位置 | 这段代码如何处理数据 | 对理解的补充 |
|---|---|---|---|

只摘录解释机制所需的短片段，余下用自己的话串联。论文没有说明但代码实现了某项处理时，写“官方实现采用……”，不要倒写成论文主张。若实现与描述有影响理解的差异，简述两者和当前采用的解释；默认不追问代码合规性、不列实验待办、不自行安装依赖或运行作者脚本。

### 没有官方代码、无法访问或关键部分未公开

继续根据已读取的论文、附录和公式解释，提供清楚标注的**教学伪代码，非官方实现，未经运行验证**。不要因没有源码把回答变成索要文件清单。

伪代码覆盖与当前问题相关的数据处理、模型前向、训练和预测恢复。应让读者看见数据流，而不是把全部计算藏进一个 `model(x)`。把核心模块单独展开到论文支持的程度：

- 论文给出算法、公式或训练步骤的部分标为 `[P]` 并注明位置。
- 为可读性安排的函数名、循环骨架、教学数值标为 `[I]`。
- 没有给出的方法或参数用明确的符号占位，如 `loss_fn（材料未说明具体形式）`、`lr（未报告）`；不要替作者选择 MSE、Adam、batch size、训练轮数或频率截断数。
- 只有来源支持某一步时才把归一化、频域处理、逆变换等写入该论文的流程。常见操作不能自动成为这篇论文的步骤。
- 若为帮助理解采用一个可能方案，在代码旁注明“示意选择，不代表作者实现”，并与论文确定流程分开。

可采用以下监督训练表达骨架，按论文实际训练范式和处理顺序改写；骨架本身不是对任何论文的事实陈述：

```text
# [I] 教学骨架；具体步骤以论文为准
# prepare 按来源展开读取、划分、预处理与取窗；未说明处明确标注
train_batches = prepare(training_data)

for batch in train_batches:                 # [I] 常规训练循环示意
    x, target = unpack_as_described(batch)
    prediction = forward_as_described(x)    # 展开论文核心模块及分支/融合
    loss = loss_fn(prediction, target)      # 具体损失/计算尺度由来源确定
    update_parameters(loss)                # 更新规则未给出时保持符号化

prediction = forward_as_described(inference_input)
result = restore_if_described(prediction)   # 仅采用来源支持的逆处理
```

可在讲解中用箭头或少量 shape 注释标示每一步的输入输出。收尾指出回读哪张结构图、哪个公式或哪段方法可以把本段解释对应回原文，无需生成独立代码文件。
